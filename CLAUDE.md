# proteomics

Differential protein abundance analysis of public label-free proteomics datasets (mouse). Like `../rna_seq`,
there is **one self-contained R script per dataset**, which can be run interactively section by section; a
Snakemake workflow chains the steps (`prepare` -> `limma_analysis` -> `report`) with parameters in `config/config.yaml`
and conda environments in `env/`.

## Layout

```
proteomics/
├── CLAUDE.md
├── .gitignore
├── Snakefile                  # workflow: prepare -> limma_analysis -> report (target of rule all)
├── config/
│   └── config.yaml            # title, groups + colors, paths, seed, filter/imputation, DE cutoffs, enrichment
├── env/                       # conda environments, one per rule (--use-conda)
│   ├── prepare.yaml           #   name: prepare  (python + xlsx2csv)
│   ├── limma.yaml             #   name: limma    (R + limma, clusterProfiler, enrichplot, org.Mm.eg.db, plots)
│   ├── report.yaml            #   name: report   (python + pandas + markdown)
│   └── <name>.linux-64.pin.txt  # exact versions (`conda list --explicit`) of each environment
├── data/                      # inputs and intermediate files
│   ├── ijms-730741-SI.xlsx    #   raw supplementary file (never edit)
│   └── processed.csv          #   tidy input for R (generated by scripts/prepare.sh)
├── scripts/                   # all code
│   ├── prepare.sh             #   xlsx -> data/processed.csv
│   ├── <model>_<author>_<method>_<accession>.R   # one analysis script per dataset
│   ├── report.py              #   builds reports/report.html (Snakemake `script:`)
│   └── html_report.py         #   report builder, copy of bulk-rna-seq/scripts/html_report.py
├── results/                   # tables only (CSV), incl. run_summary.csv (key numbers read by the report)
├── plots/                     # figures: PDF (print) + PNG (embedded in the report)
├── reports/                   # report.html (self-contained) and sessionInfo.txt
└── logs/                      # Snakemake rule logs (git-ignored)
```

## Running

```bash
export PATH=$HOME/anaconda3/bin:$PATH                       # conda must be on PATH (no mamba installed)
snakemake --cores 1 --use-conda --conda-frontend conda      # reference run: the committed results come from this
snakemake --cores 1                                         # locally installed tools (needs python `markdown`)
snakemake -n                                                # dry run
```

- **Committed results come from the conda run.** The local R uses Bioconductor devel (limma 3.99, newer fgsea),
  which gives identical limma results but slightly different GSEA counts than the pinned environment.
- **All tunable parameters live in `config/config.yaml`**; never hard-code thresholds, seeds, colors or paths in
  the scripts. The R script reads the config path from its first argument (default `config/config.yaml`), so it
  still runs standalone and interactively.
- `scripts/prepare.sh [input.xlsx] [output.csv]` takes paths as arguments (defaults: current dataset).
- When a script gains a new always-produced output, add it to `TABLES`/`FIGURES` in the `Snakefile`.
  Conditional outputs (enrichment plots, KEGG, ORA) are intentionally not declared.
- **Environments:** `env/<name>.yaml` contains `name: <name>`. New dependencies go into the matching YAML
  (including packages that are only "suggested", e.g. `r-ggridges`, `r-gridextra` for enrichplot), then
  regenerate the pin: `conda list --explicit -p .snakemake/conda/<hash>_ > env/<name>.linux-64.pin.txt`.

## Report (same model as bulk-rna-seq)

- Built in Python by the `report` rule: `scripts/report.py` reads `results/`, `plots/*.png` and
  `reports/sessionInfo.txt` and writes `reports/report.html` with `scripts/html_report.py` (floating TOC,
  KPIs, Markdown prose, embedded figures, tables, appendix with outputs/software/config/session info).
- `scripts/html_report.py` is a copy of `~/github/bulk-rna-seq/scripts/html_report.py` with two generic fixes
  (environment folder taken from the file path instead of a fixed `envs/`; YAML comments stripped from the
  package list). Keep it in sync with the bulk copy when either changes.
- Project-specific prose (design, notes, pipeline, input) lives in the `params` of the `report` rule; numbers
  in the text are computed from the tables, never hard-coded.
- **Figure code in the report:** wrap the code of each plot in `# <figure name="<plot file stem>">` /
  `# </figure>` (e.g. `volcano` for `plots/volcano.png`); the report shows it behind "Show code". Keep the
  markers when editing plot code and add them to every new plot.
- Every figure is saved as PDF + PNG (`save_plot()` for ggplot, `save_base()` for base graphics).
- **Colors (same scheme as bulk-rna-seq):** groups from `config.groups.colors` (Sham `#3399FF`, ACT `#CC0000`);
  volcano/MD plot: Up `#CC0000`, Down `#3399FF`, NS gray, via `EnhancedVolcano(colCustom = keyvals)`.

- Paths are relative to the project root. Both scripts move there themselves, so `scripts/prepare.sh` and
  `Rscript scripts/<script>.R` work from any directory; in interactive R/RStudio set the working directory
  to `proteomics/`.
- `data/` holds only inputs and intermediates; never write results or plots there.

- Script naming mirrors `rna_seq` (e.g. `ACT_cronin_DESeq2_GSE295281.R`):
  `<model>_<firstauthor>_<method>_<accession>.R`; for the current dataset: `ACT_mcelroy_limma_ijms730741.R`.
  Use the PRIDE accession (`PXD...`) when one exists, otherwise the article id (`ijms-730741`).
- Data preparation (xlsx/raw -> CSV) is done in Bash (`scripts/prepare.sh`), with inline Python only when Bash is not
  enough. R starts from the prepared CSV. Language priority: Bash > Python > R.
- Each new dataset gets its own `prepare_<accession>.sh` if more than one dataset lives here.
- Supplementary/raw files are inputs: never modify them in place.

## Current dataset: `ijms-730741-SI.xlsx`

- Source: McElroy et al. (2020), "Assessing the Effects of Redox Modifier MnTnBuOE-2-PyP 5+ on Cognition and
  Hippocampal Physiology Following Doxorubicin, Cyclophosphamide, and Paclitaxel Treatment", *Int. J. Mol. Sci.*
  (published 9 March 2020). Supplementary file id: `ijms-730741`.
- Mouse **hippocampus**; ACT = doxorubicin (A) + cyclophosphamide (C) + paclitaxel (T) chemotherapy, the same
  model as `../rna_seq/ACT_cronin_DESeq2_GSE295281.R`.
- MaxQuant output, **iBAQ** intensities. Groups in the study: Sham (sample ids 100-103),
  ACT (200-203), MnBuOE (300-303), ACT-MnBuOE (400-403); n = 4 per group.
- Table S1: annotation + raw iBAQ + normalized values, followed by two limma result blocks (not row-aligned).
  Only the raw iBAQ is used. Tables S2/S3 (proteins from the article's Tables 1/2) are not used.
- **Independent analysis.** Do not use, extract or compare against the authors' normalized values, limma
  results or protein tables; everything is derived from the raw iBAQ.
- `scripts/prepare.sh` keeps only annotation + raw iBAQ for Sham and ACT and renames samples to `Sham_1..4`, `ACT_1..4`.
  `data/processed.csv` has 5514 proteins; columns: `Protein, Protein names, Gene names, Fasta headers,
  Mol. weight [kDa], Sequence length, Sham_1..Sham_4, ACT_1..ACT_4`.
- Missing values are encoded as `0` in iBAQ: convert to `NA` before log transformation.
- `Gene names` may hold several symbols separated by `;` (protein groups): keep the first for annotation
  and ID mapping, or collapse duplicates explicitly.
- Main contrast: **ACT vs Sham** (positive logFC = higher in ACT).
- **Scope: chemotherapy effect only.** MnBuOE and ACT-MnBuOE are excluded on purpose; do not add them back
  to `data/processed.csv` or to the design/contrasts.

## Analysis script structure

Same section order as the `rna_seq` limma scripts, with `######################## Section ########################`
headers and `## Subsection` for plots:

1. **Packages** — `limma`, `dplyr`, `tidyr`, `ggplot2`, `ggrepel`, `yaml`, `clusterProfiler`, `org.Mm.eg.db`, `enrichplot`, `EnhancedVolcano`,
   `pheatmap`, `DOSE` (+ `DEP`/`imputeLCMD`/`vsn` if needed for proteomics steps; add them to `env/limma.yaml`).
2. **Adjusts** — config loading, group colors from the config, helpers `save()` (CSV), `save_plot()`, `save_base()`.
3. **Import Data** — `read.csv("data/processed.csv", check.names = FALSE)`; build sample metadata (`group` factor,
   levels `Sham`, `ACT`) from column names.
4. **Pre-processing** (proteomics-specific)
   - remove contaminants / reverse hits if flagged; `0 -> NA`; `log2` transform;
   - filter by valid values (e.g. >= 3 of 4 in at least one group);
   - normalization (median centering or VSN) — check density/boxplots before and after;
   - imputation of the remaining missing values (MinProb/QRILC for MNAR, kNN for MAR), stated explicitly.
5. **Differential expression** — `limma`: `model.matrix(~ 0 + group)`, `makeContrasts(ACT - Sham)`,
   `lmFit` -> `contrasts.fit` -> `eBayes` (consider `trend = TRUE`), `topTable(number = Inf)`.
   Significance rule: BH FDR < 0.05 and |logFC| > 0.5; **if nothing passes FDR, use unadjusted P < 0.01**
   (same |logFC|). The script picks the criterion automatically and prints which one was used.
6. **Visualization** — volcano, heatmap of DE proteins (row-scaled), boxplot, p-value/FDR histogram,
   density, QQ plot of t, MD plot, PCA of samples. **PCA and heatmap use only the batch-corrected matrix**
   (`limma::removeBatchEffect`, group protected via `design`), for visualization; the DE model never uses it
   (it estimates the batch as a term). Do not add uncorrected PCA/heatmap versions.
7. **Enrichment** — map `SYMBOL -> ENTREZID` with `bitr(OrgDb = org.Mm.eg.db)`; GSEA on GO (ALL/BP/MF/CC)
   and KEGG (`organism = "mmu"`) with the ranked logFC list; ORA of up/down sets; dotplot, ridgeplot,
   cnetplot, emapplot, gseaplot2. Use the identified proteome as background (universe) for ORA, not the
   whole genome.

## Conventions

- All code, comments and section headers in **English** (translate Portuguese when copying from `rna_seq`).
- Relative paths only (no `C:/Users/...` or absolute home paths). Tables go to `results/` (via `save()`),
  figures to `plots/` (via `save_plot()` / `save_base()`), `report.html` and `sessionInfo.txt` to `reports/`.
- Run R scripts with `Rscript scripts/<script>.R` for a full run; interactive use in RStudio is also expected.
